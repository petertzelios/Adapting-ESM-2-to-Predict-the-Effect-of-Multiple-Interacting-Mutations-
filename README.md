# Adapting ESM-2 to Predict the Effect of Multiple Interacting Mutations

Class project for CBMF 4761. Goal of the project is to use frozen ESM-2 embeddings to predict the impact of multiple simultaneous mutations in the GB-1 dataset. It explores a variety of feature engineering and secondary model strategies.

This repository contains the code and reproducibility materials for Peter Tzelios's COMS/CBMF 4761 final project on adapting ESM-2 embeddings for multi-mutation fitness prediction on the GB1 benchmark.

The project evaluates whether lightweight secondary models trained on frozen ESM-2 embeddings can improve prediction of multiple interacting mutations. The main workflow has two stages:

1. **Feature engineering from ESM-2 embeddings**: compare global sequence summaries, mutation-site embeddings, and local mutation-window embeddings.
2. **Secondary model architecture search**: compare flat ridge/MLP models against fused models that process global and local features separately.

## Notebooks

### `ESM_Loading-2.ipynb`

Original pre-midpoint notebook. This notebook contains the initial FLIP/GB1 loading, ESM-2 embedding generation/loading, feature engineering experiments, flat ridge regression experiments, and flat MLP secondary model experiments.

### `GB1_ESM2_architecture_sandbox_hybrid_training_2_CNN_debugged.ipynb`

Post-midpoint architecture sandbox. This notebook contains the fused-model work, including global/local feature preparation and sweeps over fused MLP, fused CNN, and fused attention-style local encoders.

### `GB1_ESM2_quickstart_best_CNN.ipynb`

Small reproduction notebook intended for quick grading/review. It loads the processed features or full embeddings, reconstructs the final global mean + local mutation-window representation, and trains only the best fused CNN configuration across all three FLIP splits.

Best CNN configuration used in the quickstart notebook:

- Global branch: `(128, 64)` hidden dimensions
- Local branch: 1D CNN with `384` channels, kernel size `7`, and `1` layer
- Fusion branch: `(64,)` hidden dimensions
- Dropout: `0.1`
- Optimizer: AdamW
- Learning rate: `1e-3`
- Weight decay: `1e-3`
- Batch size: `128`

## Data files

The quickstart notebook expects data files in the `data/` directory.

### Preferred quickstart file: `data/gb1_features_k5.pt`

This is the most convenient file to include for grading because it avoids regenerating or reprocessing full ESM-2 embeddings. It should be a PyTorch-saved dictionary containing:

```python
{
    "df_full": ...,        # pandas DataFrame or dict-like metadata table
    "X_seq_mean": ...,     # shape: (n_samples, 640)
    "X_window_k5": ...,    # shape: (n_samples, n_window_positions, 640)
    "feature_info": ...    # optional metadata dictionary
}
```

The metadata table must include:

- `fitness`
- `one_vs_rest`
- `two_vs_rest`
- `three_vs_rest`

The split columns should contain `train` and `test` labels.

### Full embedding file: `data/gb1_esm2_embeddings.pt`

If the processed feature cache is not included, the quickstart notebook can rebuild features from the full per-residue ESM-2 embedding file. The notebook supports a dictionary with the following expected keys or close variants:

- `X_residue` or `X` or `embeddings` or `representations`
- `Variants` / `variant` / `variants`
- `sequence` / `Sequence` / `sequences`
- `fitness` / `Fitness`
- `one_vs_rest`
- `two_vs_rest`
- `three_vs_rest`

### Optional metadata CSV: `data/gb1_splits.csv`

If the full embedding object does not contain metadata, include a CSV with at least the following columns:

- `Variants`
- `sequence`
- `fitness`
- `one_vs_rest`
- `two_vs_rest`
- `three_vs_rest`

## Running the quickstart notebook

1. Clone or download this repository.
2. Place `gb1_features_k5.pt` in the `data/` folder. If this file is unavailable, place `gb1_esm2_embeddings.pt` and, if needed, `gb1_splits.csv` in the `data/` folder.
3. Open `notebooks/GB1_ESM2_quickstart_best_CNN.ipynb` in Google Colab or Jupyter.
4. Run all cells.

The notebook writes results to:

```text
outputs/quickstart_best_cnn/
├── best_cnn_split_results.csv
├── history_one_vs_rest.csv
├── history_two_vs_rest.csv
├── history_three_vs_rest.csv
├── predictions_one_vs_rest.csv
├── predictions_two_vs_rest.csv
└── predictions_three_vs_rest.csv
```

## Reproducing the full project

For a quick reproduction of the final model, run only:

```text
notebooks/GB1_ESM2_quickstart_best_CNN.ipynb
```

For the complete project exploration:

1. Run or inspect `ESM_Loading-2.ipynb` for original data loading, ESM-2 embedding handling, feature engineering, ridge regression, and flat MLP experiments.
2. Run or inspect `GB1_ESM2_architecture_sandbox_hybrid_training_2_CNN_debugged.ipynb` for fused architecture experiments.
3. Use `GB1_ESM2_quickstart_best_CNN.ipynb` to reproduce the final selected CNN model in a smaller notebook.

## Notes on large files

The original GB1 metadata are small enough to include directly. The full per-residue ESM-2 embeddings may be large. If the embedding file exceeds GitHub's file-size limits, either:

- include only the processed feature cache `gb1_features_k5.pt`, or
- host the full embeddings externally and provide a download link in this README.

The quickstart notebook is written to prefer the smaller processed feature cache when available.

## Project caveat

The quickstart notebook mirrors the exploratory project notebooks by tracking the best test Spearman during training. For a more formal benchmark, use a separate validation set for early stopping/model selection and evaluate the test set only once.
